# fish

This repo installs a marker block into `~/.config/fish/config.fish`, but that
block is only one of several things shaping a live fish session. This file
inventories the rest — the machine-local customizations that come from
somewhere other than `.dotfiles` — so a surprising binding, variable, or prompt
can be traced to its owner without guesswork.

Audited on the `home` (mac) machine, fish 4.6.0.

## Load order

fish reads these in order; later stages can override earlier ones.

| # | What | Owner |
|---|---|---|
| 1 | `conf.d/*.fish` from `$XDG_DATA_DIRS/fish/vendor_conf.d`, `/opt/homebrew/etc/fish/conf.d`, `~/.config/fish/conf.d` — merged, sorted by filename, first name wins | vendors + machine-local |
| 2 | `/opt/homebrew/etc/fish/config.fish` | Homebrew (stock, comments only) |
| 3 | `~/.config/fish/config.fish` — OrbStack line, then the `# <<< dotfiles >>>` block, then the `# <<< clauder >>>` block | mixed |
| 4 | `~/.config/fish/functions/*.fish` | lazily autoloaded on first call |

**The consequence worth remembering:** `conf.d` runs *before* `config.fish`, so
this repo's modules load after — and can override — starship, fnm, uv, and
`REPOS_DIR`. The reverse is not true.

## Not from this repo

### `~/.config/fish/config.fish`, outside the marker block

| Line | Source | Purpose |
|---|---|---|
| `source ~/.orbstack/shell/init2.fish` | OrbStack installer | `fish_add_path -aP ~/.orbstack/bin` |
| `# <<< clauder >>>` block → `~/.clauder/shell/init.fish` | clauder installer | Defines a `claude` function routing through `clauder launch`; `claude -d` binds to the dev checkout. Real binary stays reachable as `command claude`. |

Both are self-managed by their installers. This repo's block sits between them
and neither reads nor is read by them.

### `~/.config/fish/conf.d/` — four hand-placed snippets

| File | Contents |
|---|---|
| `env.fish` | `set -gx REPOS_DIR $HOME/dev/repos` |
| `fnm.fish` | `fnm env --use-on-cd --shell fish \| source` — Node version switching on `cd` |
| `starship.fish` | `starship init fish \| source` — the prompt; config in `~/.config/starship.toml` |
| `uv.env.fish` | `source $HOME/.local/bin/env.fish`, which prepends `~/.local/bin` to `PATH` |

None are vendor-generated; all four are small enough to have been written by
hand and are candidates for adoption into the repo (see below).

### `~/.config/fish/functions/`

| File | Contents |
|---|---|
| `imgclear.fish` | Erases orphaned kitty-protocol images from the terminal (`ESC _G a=d,d=A`), with the tmux passthrough wrapping when `$TMUX` is set |

Genuinely useful and repo-shaped — currently the only local autoloaded
function, and the one piece here most clearly out of place.

### `~/.config/fish/completions/`

| Entry | Source |
|---|---|
| `copilot.fish` | Generated by GitHub Copilot CLI |
| `uv.fish` | Generated by `uv generate-shell-completion` (~750 KB) |
| `docker.fish`, `kubectl.fish`, `orbctl.fish` | Symlinks into `/Applications/OrbStack.app` |

Regenerable or vendor-owned — nothing here needs tracking.

### Vendor completions on `$fish_complete_path`

Homebrew supplies these automatically from
`/opt/homebrew/share/fish/vendor_completions.d`: `az`, `bat`, `brew`,
`databricks`, `delta`, `eza`, `fd`, `fnm`, `gh`, `ghostty`, `glow`, `mdcat`,
`orbctl`, `rclone`, `starship`, `typst`, `yq`, `zoxide`.

Ghostty prepends its `Contents/Resources` to `XDG_DATA_DIRS`, which adds its own
`ghostty` completion. Ghostty also ships a shell-integration snippet at
`Contents/Resources/ghostty/shell-integration/fish/vendor_conf.d/` — that one
only loads when Ghostty launches the shell directly with the integration path
injected, so it is *not* active in a tmux pane.

`~/.local/share/fish/vendor_functions.d`, `vendor_completions.d`, and
`/opt/homebrew/etc/fish/conf.d` are all empty or absent.

### Universal variables

`~/.config/fish/fish_variables` holds only `__fish_initialized`. No
`fish_user_paths`, no colour overrides, no stray `set -U` state. Worth
re-checking after any session that runs `fish_config` or `set -U`, since
universal variables persist invisibly and outrank everything in this repo.

## Loose ends found during the audit

- **Most `cd` abbreviations expand to nothing on this machine.** `nav.fish` and
  `git.fish` define 22 abbreviations, all of which are live. But of the
  variables they interpolate, only `REPOS_DIR` is set — and it is set by
  `conf.d/env.fish`, *outside* this repo. `DEV_DIR`, `PLAN_DIR`, `TOOLS_DIR`,
  `GWT_DIR`, `AU_REPO_DIR`, and `UC_DIR` are all empty, so `cdd`, `cdp`, `cdt`,
  `cdtp`, `cdtb`, `cdtd`, `cddt`, `cds`, `cdrw`, `cdrau`, and `cdu` currently
  expand to a bare `cd /…`. Either those variables live only on the `work`
  machine, or the definitions were lost — worth resolving before adopting
  `conf.d/env.fish` into the repo.
- **`load_aa_env` in `env.fish` is dead on this machine.** It sources
  `~/.config/.global-env/env.sh`, which does not exist, via `bass`, which is not
  installed. It fails with a readable error rather than silently.

## Adoption candidates

Ranked by how repo-shaped they are:

1. `functions/imgclear.fish` — self-contained, no external deps beyond a
   kitty-protocol terminal. Straight move into `fish/` as a module.
2. `conf.d/env.fish` — but resolve the missing `*_DIR` variables first; the
   right fix is probably one repo module defining all of them.
3. `conf.d/fnm.fish`, `conf.d/starship.fish`, `conf.d/uv.env.fish` — one line
   each. Moving them into a repo module means they load *after* the rest of the
   block instead of before it, which changes override order; check nothing in
   `env.fish` or `python.fish` depends on `PATH` already containing
   `~/.local/bin`.
4. `~/.config/starship.toml` — 20 lines, unmanaged, and the most visible part of
   the shell. Nothing in this repo would need to change to track it.

Leave alone: everything generated (`completions/`), everything installer-owned
(OrbStack, clauder), and everything vendored by Homebrew or Ghostty.
